# 产品与流程

## 定位

本项目是面向澳洲餐饮门店的 Invoice 与 Receive Note 核对工作台。供应商发票和门店
收货记录可以任意顺序到达；系统自动抽取、寻找候选并生成差异预览，用户只需校正
必要字段并确认最终结果。界面使用中文，业务原值保持英文。

系统不实现合同、完整采购订单、付款、总账或库存主数据。PO number 只是可选匹配
信号。当前 TapTouch 接口是稳定适配层，不代表已经接入真实生产 API。

TapTouch 的 external_supplier_id 只用于保护同一外部收货来源的版本链不发生供应商身份漂移；
它不会注入 Invoice，也不会替代双方 ABN/名称匹配。若同一外部收货 ID 的新版本更换供应商
ID，导入会拒绝该版本，等待上游修正或人工处理。

## 简化流程

1. 上传 Invoice 或 Receive Note；TapTouch Receiving 也可通过受保护接口导入。
2. 后台 Worker 自动提取并形成当前修订，不要求用户点击“开始提取”。
3. Invoice 自动寻找同门店 Receive Note；另一侧尚未到达时显示“等待关联单据”。
4. 用户在同一详情页查看原件、字段、候选、逐行差异和历史操作。
5. 一致结果也要确认一次；存在差异时可待核实，或填写说明后关闭。
6. 确认保存不可变快照；后续更正必须重开，旧结果永久保留。

不需要认领、分派、重复审批或手动 Start Match。“历史记录”默认列出新工作台保存的
全部正式快照，包括重开前结果；旧 Case 只保留在“旧版历史”次级只读入口。
正常结果先显示结论、自动关联的收货单和一次确认入口；候选选择默认折叠，只有关联不明
或用户主动修改时展开。字段修正和关联原因提供常用选项，普通日常操作不展示高级 JSON。

发票形成当前收货组合后，详情页左右同时展示 Invoice 与 Receive Note 原件；多张收货用
标签切换，点击逐行结果可切换到对应来源收货。上传 Receive Note 后只有在关联发票唯一
时才自动进入该发票核对页；歧义关系保留在收货详情中供人工选择，系统不猜测跳转。

历史列表可按发票号、供应商或收货单号搜索并按核对结论筛选。详情显示确认当时的逐行
结果、未核验维度、处理说明、操作人和时间；字段始终来自该次确认固定的历史修订，后续
编辑不会改写旧记录。历史页只读，可导出 CSV，不提供认领、审批或修改动作。

“未核验”表示另一方单据缺少可比较的数据，并不等于发现差异。页面对每项说明原因、
影响和处理方式，用户检查原件后可按既有规则知情确认。阻断表示关键身份、单位或数据
不安全，必须先修正；真实差异则保留原结果，并要求填写处理说明。正式历史沿用相同解释。

## 匹配与比对原则

- 先校验门店、供应商主体和币种，再使用 PO、日期、编号等信号排序候选。
- 商品优先按 SKU，缺少 SKU 时使用规范化描述；一张发票可对应多张完整收货单。
- 数量、单位、单价和金额分维度判断；缺失价格保持“未核验”，不能补成零。
- 候选分数只解释排序，不能称为概率或替代人工确认。
- 详情页显示供应商判断依据：双方可靠 ABN 相同为“按 ABN 匹配”；没有可用 ABN 但规范化名称相同为“按名称匹配”；资料不足为“供应商未核验”；资料冲突为“供应商冲突”。这只是现有规则的可视化，不改变匹配结果。
- 相同文件 Hash 的重复上传返回原记录；同店同编号发票在确认前阻断，不自动删除。
- 一张收货单被正式结果占用后，不能同时用于另一张发票。

## 状态含义

| 状态 | 用户看到的含义 |
|---|---|
| processing | 后台正在处理 |
| waiting_counterpart | 另一侧单据尚未到达 |
| needs_attention | 字段、来源或差异需要核实 |
| awaiting_confirmation | 预览已生成，等待一次确认 |
| completed | 已保存不可变正式结果 |
| failed / cancelled / voided | 失败、取消或作废，不伪装成完成 |

## 外部参考边界

MatchFlow/invoice-processor 只用于参考列表搜索筛选、紧凑状态展示、详情信息聚合，以及
Controller/Application/Repository/Infrastructure 的分层表达。本项目不采用它的 PO
业务、手动匹配、模拟进度、三字段置信度、缺失值补零、localStorage JWT、同步 OCR
上传或硬编码 Dashboard 指标。

## 后续范围

当前业务功能 Spec 已覆盖新工作台历史查询。真实上线前仍需真实 TapTouch 契约、正式身份与 Secret
基础设施、事件重试告警和真实业务样本。部分收货数量分配只有在真实样本证明必要时
才进入新 Spec；不提前增加企业审批或两套工作流。
