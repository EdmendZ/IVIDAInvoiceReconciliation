# 结构化抽取模型选择记录

## 决策原则

本项目不把“能力最强的通用模型”直接等同于“最合适的抽取模型”。候选模型
使用相同的 MinerU 解析缓存、Prompt、Pydantic Schema 和合成 Gold 数据评测，
关注以下指标：

1. Schema 通过率；
2. 字段 micro accuracy；
3. 行项目 F1；
4. 字段证据覆盖率；
5. P50/P95 归一化延迟；
6. 单文档估算成本。

只有通过成本约束的候选模型才进入准确率排序。价格未配置时，系统明确显示
`not configured`，不会把未知成本当成零成本。

## 为什么使用 MinerU + 文本模型

MinerU 负责版面、表格和 OCR，结果按原件 SHA-256 缓存；文本模型只负责把
解析结果归一化为 Invoice/Receive Note Schema。这一拆分便于：

- 独立定位 OCR 错误与语义归一化错误；
- 更换 Prompt 或文本模型时不重复支付文档解析成本；
- 保存字段证据，支持人工审核；
- 用确定性 Python 规则完成财务差异判定，避免让模型直接作审批决定。

公共视觉模型可以作为后续对照组，但不是当前默认链路。它需要在同一 Gold
数据集上证明端到端准确率、证据定位、延迟或成本更优，才能替换现有拆分。

## API 参数选择

- 启用 `response_format={"type": "json_object"}`；
- 非思考模式用于结构化抽取；
- 默认不限制最大输出 Token，避免长行项目 JSON 被中途截断；
- SDK 隐式重试设为 0，由 Worker 负责可审计的业务重试；
- 返回内容仍经过 JSON 解析和 Pydantic Schema 校验。

阿里云官方结构化输出文档列出了支持 JSON Mode 的 Qwen Max、Plus 和
Flash 系列，并明确提示启用结构化输出时不要人为限制输出 Token，以免 JSON
被截断。官方也将 Plus 描述为效果、速度和成本较均衡的选择。因此实验顺序为：

1. `qwen3.7-max`：质量基线；
2. `qwen3.5-plus` 或当前 Plus：成本/速度候选；
3. 当前 Flash：低成本候选及 JSON 修复兜底。

## 当前冒烟结果

2026-07-31 使用一份合成澳洲披萨采购发票验证链路：

| 指标 | 结果 |
|---|---:|
| Schema 通过率 | 100% |
| 字段准确率 | 89.47% |
| 行项目 F1 | 100% |
| 证据覆盖率 | 89.47% |
| MinerU 缓存命中 | 是 |
| 归一化延迟 | 71.7 秒 |
| 成本 | 未配置 |

主要错误为供应商名称受到页面合成水印干扰，以及三个行号未抽取。该结果只
证明评测链路可运行，不足以选择最终模型。下一步必须跑满 17 份文档并加入
Plus/Flash 对照。

初次报告曾把证据覆盖率显示为 34.21%。根因是模型返回路径带
`document.` 前缀，而评测器按无前缀路径匹配。修复评测器后用保存的预测结果
离线复算为 89.47%，没有再次调用模型。该案例说明评测代码本身也必须有测试
和可复算输出。

## 面试陈述边界

可以陈述：

- 完成了真实 API 链路、缓存、Schema 校验、证据映射和可复现评测；
- 已得到单文档冒烟指标，并识别出具体错误类型；
- 已设计 Max/Plus/Flash 的成本约束对比。

不能陈述：

- 已选出生产最优模型；
- 单文档结果可以代表真实客户数据；
- 系统能够完全自动审批财务单据。
