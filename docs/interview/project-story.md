# IVIDA Invoice Reconciliation 项目故事

## 一句话介绍

这是一个面向餐饮采购场景的 AI 辅助单据审核 Pilot：将供应商 Invoice 与门店
Receive Note 转成带证据的结构化数据，人工确认后，再由确定性规则完成一对多
核对。

## 为什么要做

一张供应商发票可能对应同一采购订单下的多次收货。人工需要检查商品、数量、
单价、税额和总额，容易漏掉短收、未开票商品、重复收货或订单号不一致。

## 核心设计

1. 原件进入 MinIO，任务和审核状态进入 PostgreSQL。
2. MinerU 解析 PDF/图片的版面、文字和表格。
3. LLM 将解析结果归一化为 Invoice 或 Receive Note Schema，并返回字段证据。
4. Pydantic 和财务规则检查 Schema、行金额、税额与总额。
5. 人工核对原文证据，必要时创建修订版本，然后批准。
6. 只有不可变的批准版本可以进入对账。
7. Python 规则按采购订单和商品行进行一对多汇总，输出可解释差异。

LLM 负责理解非结构化单据，不直接决定付款或审批结果。

## 大模型工程亮点

- Provider 抽象允许更换公共模型或私有部署模型。
- 保存解析模型、归一化模型、Prompt 指纹、Token、延迟和估算成本。
- MinerU 结果按原件 SHA-256 缓存，模型/Prompt 对比不重复 OCR。
- 合成澳洲披萨采购数据包含 8 个场景、17 份单据和 Gold JSON。
- 评测覆盖 Schema 通过率、字段准确率、行项目 F1、证据覆盖率、延迟和成本。
- 单文档失败会被记录并继续评测，避免幸存者偏差。
- 保存预测 JSON 和证据路径，可离线复算指标。

## 当前边界

当前交付是本机演示 Pilot，不声称具备高可用、多租户、灾备、四眼审批、
恶意文件扫描或完整财务合规能力。数据为合成材料，单文档冒烟结果不能外推
到真实客户数据。

生产演进会优先补充真实脱敏数据评测、模型成本对照、Worker 多实例租约、
四眼审批、对象存储安全策略、监控告警和灾备演练。
