# 中文界面与合同边界

## 用户原话

“1.先把之前的项目改为中文版 但是数据仍然是英文数据 2.你觉得合同适用与taptouch的业务范围吗”

## 已确认与实施范围

用户要求中文界面、保留英文数据。本次翻译导航、表单、操作、状态标签及常见系统提示；不翻译原始单据、商品、供应商、人工说明，不改变 API 字段和状态值，也不改变 AUD/GST 业务口径。仅做界面本地化，没有实施上一轮建议的业务规则重构。

## 助手建议（未确认实施）

合同适合作为连锁餐饮供应商采购协议的可选上游依据，约束协议价格、有效期、付款账期、最低采购量、配送与退换货条款。但现有资料未证实 TapTouch 生产系统拥有合同管理功能，也未获得真实合同样本或接口，不能声称已经支持或接入。

推荐日常主流程仍为订单（若上游可提供）→ 收货 → 发票；有协议时关联协议条款核验，无协议时允许正常核对。采购协议可由文件上传/人工录入，不必重做合同起草、签署和法务审批系统。

课程 2.5.3 要求包含合同、订单、发票。可使用“有供应协议的连锁门店采购”作为演示场景覆盖课程，并把合同设置为可选业务依据；这仍需用户确认，不把课程范围冒充 TapTouch 已存在功能。
